## Session: 2026-01-05 (Previous) - Event Admin Page Redirect FIX COMPLETE ✅

### Issue
Superadmin (director@jkkn.ac.in) couldn't access `/admin/events/appathon-2` - page kept redirecting to `/admin/events` list.

### Root Causes Found & Fixed

**Root Cause #1: get_user_role RPC function (Database)**
- Function in migration 019 referenced `institution_id` column which doesn't exist
- Correct column name is `institution` (TEXT)
- Created migration `092_fix_get_user_role_column.sql`
- Applied to production Supabase via SQL Editor

**Root Cause #2: Event admin page query (Code)**
- `/app/(admin)/admin/events/[slug]/page.tsx` was selecting non-existent columns:
  - `methodology` - doesn't exist (stored in `config` jsonb)
  - `status` - doesn't exist (table has `is_active` boolean)
- Query was failing, triggering redirect to `/admin/events`

### Fixes Applied

**Database Fix:**
```sql
DROP FUNCTION IF EXISTS get_user_role(UUID);
CREATE OR REPLACE FUNCTION get_user_role(user_id UUID)
RETURNS TABLE(role TEXT, institution TEXT) AS $$
BEGIN
  RETURN QUERY
  SELECT u.role, u.institution  -- Fixed: was institution_id
  FROM public.users u
  WHERE u.id = get_user_role.user_id
  LIMIT 1;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

**Code Fix:**
- Changed select from: `id, name, slug, methodology, status, start_date, end_date`
- Changed select to: `id, name, slug, is_active, config, start_date, end_date`
- Changed `event.status === 'active'` to `event.is_active === true`

## Previous Session: 2026-01-04 - BUG-127 Builder Count Fix

### What Was Done

**BUG-127: Builder count remains static on event page - FIXED ✅**

**Problem:** Builder count showed 1337 instead of expected ~1500+. Users who switched events were no longer counted for their previous event because `active_event_id` only tracks the CURRENT event.

**Root Cause Analysis:**
- `get_event_builder_count()` function used `WHERE active_event_id = event_id`
- When users switch events, they lose their count in the previous event
- Need to count ALL users who ever registered (via cycles table)

**Solution: UNION-based approach**
Created new RPC functions that count:
1. Users currently active on the event (`active_event_id`)
2. Users who have cycles for the event (historical registrations)

**Database Changes:**
- Created `get_event_registered_builder_count(UUID)` - single event count
- Created `get_all_event_registered_builder_counts()` - all events count
- Both use UNION to combine active users + cycle users

**Code Changes:**
| File | Change |
|------|--------|
| `supabase/migrations/088_registered_builder_count.sql` | Initial migration |
| `supabase/migrations/089_fix_registered_builder_count.sql` | UNION-based fix |
| `app/(admin)/admin/events/[slug]/page.tsx` | Uses new RPC function |
| `app/api/events/route.ts` | Uses `get_all_event_registered_builder_counts` |

**Commits:**
- `fbe4590` - fix(admin): Use UNION-based builder count for accuracy
- `d7a166a` - fix(api): Use registered builder count in events API

**Result Verified:**
- Old count: **1337** (only active users)
- New count: **1397** (active + historical via cycles)
- 60 additional builders now correctly counted
