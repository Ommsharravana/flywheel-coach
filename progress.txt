### Fixed Total Cycles Showing 1000 Bug (2025-12-31)

**Bug Report:** "total cycles is constant at 1000. it is updating in realtime"
**Page:** `/admin/cycles`

**Root Cause:**
- Supabase RPC functions return max 1000 rows by default
- Stats were calculated client-side from `cyclesData.length` (capped at 1000)
- Aggregate queries (COUNT) bypass this limit since they return single rows

**Solution:**
- Created new RPC function `get_cycle_stats_admin()` that returns aggregate counts directly
- Updated `admin/cycles/page.tsx` to use dedicated stats RPC instead of array.length

**Files Created:**

### Root Cause Analysis
1. Production had old function `get_event_submissions(UUID)` with ONE parameter
2. Code called with TWO parameters: `(target_event_id, caller_user_id)`
3. Signature mismatch caused silent failure returning empty results
4. Director WAS already in event_admins (initial blocker diagnosis was wrong)

### Fix Details
Migration 060 added:
- `has_event_access_explicit(UUID, UUID, TEXT)` - checks event access with explicit user_id
- `get_event_submissions(UUID, UUID)` - accepts explicit caller_user_id
- `update_submission_review(UUID, TEXT, NUMERIC, TEXT, UUID)` - accepts explicit caller_user_id

### Lesson Learned
**Supabase Cloud doesn't auto-apply migrations from the migrations folder.**
Always verify migrations are applied after deployment by checking function signatures.

**Migration 056 Bug Pattern:**
When API returns generic "Failed to search users" error, check if RPC function signature matches what API is calling. Partial migrations (column exists but function not updated) cause silent failures.
